# Agent 评测综述解读

> 原文：[A Survey on Evaluation of LLM-based Agents](https://arxiv.org/html/2503.16416v2) ｜ 已录入 `data/papers.yml`，附配套基准仓库

## TL;DR

把 agent 评测按**能力维度（规划/工具使用/反思/记忆/多 agent 协作）× 评测方法（结果/轨迹/过程指标）**组织成系统地图，并整理了全部主流基准。结论直言：领域内评测碎片化严重，多数论文只在自选基准上自证。

## 核心框架

1. **按能力拆评测**：不要只测「任务成功率」——规划（步骤合理性）、工具使用（选对工具/参数）、反思（错误恢复）、记忆（跨会话保持）各自需要独立度量；
2. **按方法分层**：最终结果评测最常用但最粗糙；轨迹评测信息量大但需要 trace 基建；过程指标（token 成本、步数、人工介入率）常被论文忽略但对生产至关重要；
3. **基准盘点**：配套仓库汇总数十个基准的适用范围与已知缺陷（污染、饱和）。

## 值得记的结论

1. **过程指标应与结果指标同权重报告**——一个成功率 90% 但平均 200 步的 agent 可能毫无商用价值；
2. 多 agent 系统的评测最不成熟：涌现协作难以归因到单 agent；
3. 「Agent-as-a-Judge」是补偿人工评测稀缺的务实方向，但评委自身的可靠性需要抽样人审锚定。

## 局限与批评

- 基准清单更新速度赶不上领域（出版即落后半年）；
- 对企业私有场景评测（自建 case 库方法）着墨少——而这恰是实践者最需要的。
